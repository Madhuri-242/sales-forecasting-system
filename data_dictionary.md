# Data Dictionary — Sales Forecasting System

## 1. Overview

This document describes the synthetic datasets generated by the Sales Forecasting System. The data represents sales territories, representatives, customer accounts, sales opportunities, forecast snapshots, activities, quotas, historical bookings, and territory changes.

The datasets are generated locally using Python, Pandas, NumPy, and Faker. They are intended for development, data-quality validation, and sales forecasting analysis.

## 2. Dataset Reference

| CSV file | Purpose |
|---|---|
| `territory.csv` | Sales territory master data |
| `sales_rep.csv` | Sales representative details and assigned territories |
| `account.csv` | Customer account details and associated territories |
| `opportunity.csv` | Sales opportunities, stages, dates, amounts, and forecast values |
| `forecast_snapshot.csv` | Periodic snapshots of opportunity forecast values |
| `stage_history.csv` | Recorded initial stage entries for a subset of opportunities |
| `activity.csv` | Sales activities associated with opportunities and representatives |
| `historical_booking.csv` | Booking records generated for opportunities marked Closed Won |
| `quota.csv` | Sales representative targets for 2026 Q1 |
| `territory_history.csv` | Territory-change records for a subset of representatives |
| `ground_truth.csv` | Reference labels identifying five intended anomaly categories |

## 3. Column Definitions

### 3.1 `territory.csv`

| Column | Description |
|---|---|
| `territory_id` | Unique territory identifier, such as `TER-001` |
| `territory_name` | Display name of the territory |

### 3.2 `sales_rep.csv`

| Column | Description |
|---|---|
| `rep_id` | Unique sales representative identifier |
| `rep_name` | Synthetic representative name generated by Faker |
| `territory_id` | Identifier of the representative's assigned territory |

### 3.3 `account.csv`

| Column | Description |
|---|---|
| `account_id` | Unique customer account identifier |
| `account_name` | Synthetic company name generated by Faker |
| `territory_id` | Identifier of the account's associated territory |

### 3.4 `opportunity.csv`

| Column | Description |
|---|---|
| `opp_id` | Unique opportunity identifier |
| `account_id` | Account associated with the opportunity |
| `rep_id` | Representative associated with the opportunity |
| `amount` | Opportunity amount in unspecified monetary units |
| `stage` | Current assigned sales stage |
| `create_date` | Date the opportunity was created |
| `expected_close_date` | Expected closing date |
| `actual_close_date` | Generated actual closing date; currently assigned to every opportunity regardless of stage |
| `slippage_days` | Number of days the generated actual date is later than the expected date |
| `opportunity_age` | Number of days between creation and generated actual closing date |
| `is_stale` | `Y` if opportunity age exceeds 120 days; otherwise `N` |
| `probability` | Forecast probability assigned according to the sales stage |
| `forecast_amount` | Stage-weighted forecast amount, calculated as `amount × probability` |

**Stage probabilities**

| Stage | Probability |
|---|---:|
| Prospecting | 0.10 |
| Qualification | 0.25 |
| Proposal | 0.50 |
| Negotiation | 0.75 |
| Closed Won | 1.00 |
| Closed Lost | 0.00 |

### 3.5 `forecast_snapshot.csv`

| Column | Description |
|---|---|
| `snapshot_id` | Unique snapshot record identifier |
| `opp_id` | Opportunity associated with the snapshot |
| `snapshot_date` | Date of the forecast snapshot |
| `forecast_amount` | Forecast amount copied from the generated opportunity record |
| `probability` | Probability copied from the generated opportunity record |

Snapshot dates are quarterly dates from March 2025 through December 2026. Only opportunities created on or before a snapshot date are included.

**Important limitation:** Historical snapshots currently reuse the opportunity's final generated stage, probability, and forecast amount. They do not reconstruct the information available at each historical date, so they are not yet suitable for leakage-free historical forecast evaluation.

### 3.6 `stage_history.csv`

| Column | Description |
|---|---|
| `stage_history_id` | Unique stage-history record identifier |
| `opp_id` | Associated opportunity |
| `stage_name` | Stage recorded in the history entry |
| `change_date` | Date associated with the recorded stage |

The current generator creates one initial stage-history entry for a subset of 1,000 opportunities. It does not simulate a complete sequence of stage transitions.

### 3.7 `activity.csv`

| Column | Description |
|---|---|
| `activity_id` | Unique activity identifier |
| `opp_id` | Associated opportunity |
| `rep_id` | Representative associated with the activity |
| `activity_type` | Activity category: Call, Email, Meeting, or Demo |
| `activity_date` | Generated activity date, currently equal to the opportunity creation date |

The generator creates one activity for each of the first 2,000 opportunities.

### 3.8 `historical_booking.csv`

| Column | Description |
|---|---|
| `booking_id` | Unique booking identifier |
| `opp_id` | Associated opportunity |
| `booking_amount` | Opportunity amount copied into the booking record |
| `booking_date` | Generated actual closing date |

The current generator creates booking records for opportunities assigned the Closed Won stage. The records are synthetic and should not be interpreted as independently verified real-world bookings.

### 3.9 `quota.csv`

| Column | Description |
|---|---|
| `quota_id` | Unique quota record identifier |
| `rep_id` | Sales representative associated with the quota |
| `quarter` | Quota period; currently `2026Q1` |
| `target_amount` | Generated sales target for the representative |

The generator creates one quota record per sales representative for 2026 Q1.

### 3.10 `territory_history.csv`

| Column | Description |
|---|---|
| `history_id` | Unique territory-history record identifier |
| `rep_id` | Representative whose territory changes |
| `old_territory_id` | Generated previous territory identifier |
| `new_territory_id` | Generated new territory identifier |
| `change_date` | Recorded territory-change date |

The generator creates 200 territory-change records dated 2026-01-01. These changes are not integrated into historical forecast snapshots.

### 3.11 `ground_truth.csv`

| Column | Description |
|---|---|
| `issue_id` | Identifier for the reference issue |
| `opp_id` | Opportunity identifier associated with the label |
| `issue_type` | Intended anomaly category |

The current file contains five reference labels:

- `LEAKAGE`
- `INVALID_DATE`
- `PROBABILITY_MISMATCH`
- `DUPLICATE_OPPORTUNITY`
- `CURRENCY_MISMATCH`

**Important limitation:** These labels are currently reference entries only. The generator does not deliberately inject the corresponding anomalies into the datasets. In particular, there is no currency field or currency-conversion data in the current opportunity dataset.

## 4. Relationships Between Datasets

- `sales_rep.territory_id` references `territory.territory_id`.
- `account.territory_id` references `territory.territory_id`.
- `opportunity.account_id` references `account.account_id`.
- `opportunity.rep_id` references `sales_rep.rep_id`.
- `forecast_snapshot.opp_id` references `opportunity.opp_id`.
- `stage_history.opp_id` references `opportunity.opp_id`.
- `activity.opp_id` references `opportunity.opp_id`.
- `activity.rep_id` references `sales_rep.rep_id`.
- `historical_booking.opp_id` references `opportunity.opp_id`.
- `quota.rep_id` references `sales_rep.rep_id`.
- `territory_history.rep_id` references `sales_rep.rep_id`.
- `ground_truth.opp_id` identifies the opportunity associated with a reference label.

These describe the intended logical relationships. Database constraints should be checked against the actual SQL schema.

## 5. Data Generation and Validation

The generator creates synthetic data with identifiers for linking related records. The validation script checks opportunity identifiers, date consistency, missing values, allowed stages, account and representative references, forecast calculations, and opportunities appearing before their creation dates in snapshots.

Previously recorded validation results include:

- 20,000 opportunities
- 2,000 sales representatives
- 2,000 accounts
- 103,628 forecast snapshots
- Zero duplicate opportunity IDs
- Zero invalid account references
- Zero invalid representative references
- Zero incorrect forecast calculations
- Zero opportunities created after their snapshot dates

These are results from a previously reported run, not a guarantee that every future run will produce identical results.

## 6. Known Limitations

1. All data is synthetic and does not represent actual customers or sales.
2. Historical snapshots reuse final opportunity values, creating a risk of temporal data leakage.
3. Opportunity stages are randomly assigned rather than simulated through realistic stage transitions.
4. Actual closing dates are generated even for opportunities that are not marked Closed Won or Closed Lost.
5. Stage history and activity coverage are limited to subsets of opportunities.
6. Quota coverage currently includes only 2026 Q1.
7. Ground-truth anomaly labels are not backed by injected anomalies yet.
8. Currency mismatch detection is not currently supported by the generated schema and data.
9. The forecast amount is a stage-weighted estimate, not a trained predictive forecasting model.

These limitations should be considered when interpreting forecast results or extending the project.
